# Martini MT

노트북 한 대로 조와 참가자 명단을 관리하고, 발표 화면의 QR로 휴대폰을 참가자에게 연결하는 웹 앱입니다. GitHub Pages + Firebase Authentication + Realtime Database를 사용합니다.

## 진행 순서

1. **관리자는 노트북에서 사이트의 기본 주소를 엽니다.** 처음 접속하면 이 브라우저의 익명 로그인으로 행사 한 개를 만듭니다.
2. 행사 이름, 네 개 조의 이름, 각 조 참가자 실명을 수기로 입력합니다. 조별 6명까지 등록하고 빈칸은 제외합니다.
3. **명단 저장 → 발표 시작**을 누릅니다. 발표 화면으로 전환되며 QR과 입장 현황이 표시됩니다. 브라우저 전체화면은 사용자가 F11로 켭니다.
4. 참가자는 QR로 들어가 **등록된 실명**을 입력합니다. 동명이인이 있으면 조를 선택합니다.
5. 이름에 대응하는 참가자 ID와 해당 브라우저의 인증 UID가 연결됩니다. 이미 다른 기기가 연결된 사람은 중복 입장할 수 없습니다.
6. 관리자가 **채팅 시작 →**을 누르면 각 휴대폰 화면도 채팅으로 전환됩니다. 전체 채팅과 자신의 조 채팅을 사용할 수 있습니다.
7. 관리 화면의 참가자별 **안내** 버튼으로 특정 휴대폰에 안내를 보냅니다. 참가자가 **확인했어요**를 누르면 관리자에게 반영됩니다.

기기를 바꿔야 하면 참가자 행의 연결 해제 버튼을 사용합니다. 현재 연결을 해제한 후 새 기기에서 이름을 입력합니다.

## 중요한 구분

- 관리 주소는 기본 사이트 주소입니다. 참가자 주소는 QR에 담긴 `?room=행사ID` 주소입니다.
- 행사 관리 권한은 **행사를 만든 브라우저의 Firebase 로그인**에 연결됩니다. 다른 컴퓨터가 같은 행사 주소를 알아도 명단을 읽거나 수정할 수 없습니다.
- 노트북의 브라우저 데이터를 삭제하거나 시크릿 창을 닫으면 기존 관리 로그인을 잃을 수 있습니다. 실제 행사에서는 같은 브라우저 프로필을 유지하세요.
- 실명 입력은 명단 매칭이며 본인 인증은 아닙니다. 초대받은 사람이 자기 이름을 입력하는 행사 운영을 전제로 합니다.
- 참가자는 명단 전체와 다른 사람의 개인 안내를 읽을 수 없습니다. 전체 채팅은 행사 참가자가 공유하고 조별 채팅은 해당 조와 관리자만 읽습니다.
- 현재 구현된 발표 단계는 **입장 안내·실시간 채팅**입니다. 개별 안내와 확인 응답을 향후 레크레이션 동작에 확장할 수 있습니다.

## Firebase 설정

루트의 **`firebase-config.js`**에 공개 웹 설정을 입력합니다. 현재 기존 `martinimt-9c21f` 웹 앱 설정이 채워져 있습니다. 다른 프로젝트를 연결할 때는 `firebase-config.example.js`를 참고하세요.

이 파일에는 서비스 계정 JSON, 비공개 키, Admin SDK 키, OAuth 토큰을 넣으면 안 됩니다. 공개 웹 설정은 빌드 결과에 포함되며, 권한은 Authentication과 Security Rules로 제어합니다.

`appCheckSiteKey`는 선택적인 reCAPTCHA v3 공개 사이트 키입니다. App Check 강제 적용은 별도 승인 후 진행합니다.

## 로컬 개발

### 화면 스타일

색상·글자·간격 공통 토큰은 `src/design-tokens.css`, 화면별 스타일은 `src/event-style.css`에서 관리합니다. 차콜 배경과 골드 행동 버튼을 사용하며, 명단 관리·발표·참가자 페이지의 기존 기능과 구성을 유지합니다. 관리 화면에는 사진이나 홍보용 히어로를 사용하지 않습니다. 관리자 화면은 최소 1120px의 컴퓨터용 네 조 배치를 사용하고, QR로 연결하는 참가자 화면은 모바일 폭과 터치 입력에 맞춥니다.

Pretendard Variable은 설치한 패키지의 동적 서브셋을 빌드에 포함해 필요한 글자 파일만 로드합니다. 별도 폰트 CDN 연결 없이 동작합니다. 아이콘은 Lucide의 사용 항목만 포함합니다. 글꼴과 아이콘 라이선스는 `public/licenses/`에 있습니다.

Node.js 22.12 이상을 사용합니다.

```powershell
npm ci
npm run dev
```

노트북에서는 `http://localhost:5173/`로 접속합니다. 휴대폰은 같은 Wi-Fi에 연결한 뒤 터미널에 표시된 **Network 주소**로 접속합니다. 휴대폰의 localhost는 노트북을 가리키지 않습니다. 공유기의 기기 간 통신 및 Windows 방화벽 설정에 따라 접근이 달라질 수 있습니다.

개발 서버에서는 소스를 저장하면 화면이 갱신됩니다. GitHub Pages 화면은 새 빌드가 배포된 후 바뀝니다.

## 배포

운영 반영은 `SECURITY.md`의 승인 경계를 따릅니다.

1. Firebase Authentication의 익명 로그인을 활성화합니다.
2. 사용할 인증 도메인을 확인합니다. 도메인 설정만으로 데이터베이스 접근이 보호되지는 않습니다.
3. 변경한 규칙을 로컬 에뮬레이터에서 검증합니다. 규칙 생성 원본은 `scripts/generate-rules.mjs`입니다.

   ```powershell
   node scripts/generate-rules.mjs
   ```

4. 명시적 승인 후 규칙을 배포합니다.

   ```powershell
   firebase deploy --only database --project martinimt-9c21f
   ```

5. GitHub 저장소 Settings → Pages → Source를 **GitHub Actions**로 설정합니다.
6. 승인된 `codex/live-chat` 또는 `main` 푸시는 `.github/workflows/pages.yml`에서 검사·빌드·게시됩니다. main 직접 푸시는 하지 않습니다.

게시 주소: `https://nacha4.github.io/MartiniMT/`

현재 구조에는 Cloud Functions나 관리자 키가 필요하지 않습니다. 요금제를 코드로 변경하지 않습니다.

## 검증

```powershell
npm test
npm run build
```

Firebase CLI와 Java 21 이상을 준비하고 별도 터미널에서 로컬 에뮬레이터를 실행합니다.

```powershell
firebase emulators:start --only auth,database --project demo-martini-mt
```

다른 터미널:

```powershell
$env:FIREBASE_DATABASE_EMULATOR_HOST = '127.0.0.1:9000'
npm run test:rules
npm run test:e2e
```

브라우저 검사는 설치된 Chrome을 사용합니다. 에뮬레이터 화면은 `npm run dev:emulators`로 열며 **로컬 테스트** 표시가 붙습니다. 운영 데이터와 연결되지 않습니다.

검증 범위: 행사 소유자 권한, 명단 비공개, 동명이인 조회, 기기 연결 원자성, 동시 중복 연결 차단, 관리자 연결 해제, 개인 안내와 응답의 접근 제한, 채팅 단계·조별 읽기 제한, 작성자 위조·수정·삭제·과도한 연속 전송 차단, 참가자 24명+관리자 1명의 동시 통신, QR 진입, 실제 브라우저 간 채팅, 재접속.

## 데이터와 운영

- 경로는 `/mtChatV1/sessions/{행사ID}`이며, 다른 데이터 경로는 기본 차단입니다.
- 메시지는 화면에 최근 100개만 받습니다. 과거 메시지와 행사가 자동 삭제되지는 않습니다.
- 이름, 조, 기기 연결 정보와 채팅은 Firebase에 보관됩니다. 보존·삭제 정책은 별도로 정해야 합니다.
- 전송 중 페이지를 닫으면 전송이 보장되지 않습니다. 접속자 상태에는 네트워크에 따른 지연이 있을 수 있습니다.
- 실제 휴대폰 24대와 현장 Wi-Fi에서 최종 리허설을 권장합니다.
