# Martini MT

노트북 한 대로 조와 참가자 명단을 관리하고, 발표 화면의 QR로 휴대폰을 참가자에게 연결하는 웹 앱입니다. GitHub Pages + Firebase Authentication + Realtime Database를 사용합니다.

## 진행 순서

1. **관리자는 노트북에서 사이트의 기본 주소를 엽니다.** 운영 사이트는 `SINGLE_EVENT_ROOM`에 지정된 기존 행사 하나를 엽니다. 새 기기는 등록된 관리자 이름으로 로그인하며, 원래 행사 소유자의 브라우저는 바로 관리 화면을 엽니다.
2. 고정된 **1조·2조·3조·4조**에 참가자 실명을 입력합니다. 조별 6명까지 등록하고 빈칸은 제외합니다. 입력 내용은 즉시 브라우저에 저장하고, 입력이 잠시 멈추면 Firebase에도 자동 저장합니다. 연결이 복구되면 저장을 재개하며, 상단에서 저장 상태와 입력 오류를 확인할 수 있습니다.
   휴대폰으로 진행하려면 **관리자 이름**도 입력합니다. 관리자 이름은 별도로 자동 저장됩니다.
3. **발표 시작**을 누릅니다. 최신 명단의 저장이 완료된 뒤 QR과 실시간 입장 현황이 한 화면에 표시됩니다. 오른쪽 위 **전체화면** 버튼이나 F11로 전체화면을 켭니다.
4. 참가자는 QR로 들어가 **등록된 실명**을 먼저 입력합니다. 동명이인이 있으면 조를 선택합니다. 입장 후 휴대폰을 **가로로 돌리고 전체화면으로 시작**합니다. 이름 입력은 세로 화면에서도 가능합니다.
5. 이름에 대응하는 참가자 ID와 해당 브라우저의 인증 UID가 연결됩니다. 이미 다른 기기가 연결된 사람은 중복 입장할 수 없습니다.
6. 입장한 휴대폰에는 **대기 중**이 표시됩니다. 노트북 발표 화면의 빈 곳을 **좌클릭**하면 선착순 터치가 시작되고, 각 휴대폰에 **터치하세요!** 버튼이 나타납니다.
7. 가장 먼저 서버에 접수된 참가자의 **이름과 조만** 노트북에 표시됩니다. 해당 참가자의 휴대폰에는 **가장 먼저 터치했습니다!**, 나머지 휴대폰에는 **마감되었습니다**가 표시됩니다. 전송 중이던 입력도 현재 라운드 결과로 전환됩니다.
8. 게임 화면에서 **우클릭**하면 QR 화면으로 돌아가고, 다시 좌클릭하면 새 라운드를 시작합니다. QR 화면에서 **우클릭**하면 명단과 관리자 이름을 입력하는 초기 설정 화면으로 돌아갑니다. 이전 라운드 응답은 제외됩니다. Esc로도 발표를 종료합니다. 전체화면에서는 Esc를 먼저 눌러 전체화면을 해제한 뒤 한 번 더 누릅니다.

기기를 바꿔야 하면 참가자 행의 연결 해제 버튼을 사용합니다. 현재 연결을 해제한 후 새 기기에서 이름을 입력합니다.

## 관리자 휴대폰

같은 QR로 접속해 등록한 관리자 이름을 입력하면 관리자 리모컨이 열립니다. 기본 사이트 주소에서 같은 이름으로 로그인하면 명단과 퀴즈를 편집하고 발표할 수 있습니다. 공용 행사는 여러 관리자 기기를 함께 연결하며, 새로고침 후에도 로그인을 유지합니다. 관리자 이름을 아는 사람에게 관리 권한이 부여되므로 공유 범위를 관리해야 합니다.

- 이전·다음 화면 이동. 발표 시작은 노트북의 행사 관리 화면에서 진행
- 가로 전체화면에서 리모컨 UI를 90° 회전해 세로로 사용하며, 버튼을 스크롤 없이 한 화면에 표시
- 리모컨 하단에 이전 화면·다음 화면 버튼 고정

리모컨은 QR 화면의 배치를 기본으로 모든 화면에서 상단 약 1/3을 진행 대본 영역으로 유지하고, 하단에 이전 화면·다음 화면 버튼을 고정합니다. 가운데 영역은 비워 두고, 대본이 없는 화면에서는 대본 영역도 비워 둡니다. 대본 영역 안에서 스크롤할 수 있으며, 접속 현황이 갱신되어도 읽던 위치를 유지합니다. QR 화면에서 이전 화면을 누르면 노트북의 초기 설정 화면으로 돌아갑니다. 초기 설정 중에는 두 이동 버튼을 비활성화합니다.

진행 화면에서는 더블탭·핀치 확대, 길게 눌러 선택하기와 기본 스크롤 제스처를 차단하고, 화면 이동과 전체화면 전환 후 0.4초 동안 중복 입력을 제한합니다. 버튼을 쓸어 넘긴 뒤 생기는 클릭과 키를 누르고 있어 발생하는 반복 이동도 걸러냅니다. 대본은 전용 터치 스크롤로 읽으며, 전체화면이 해제되어도 읽던 위치와 현재 라운드를 보관합니다. 전체화면 시작이 실패하면 같은 버튼으로 다시 시도할 수 있습니다. Safari·운영체제의 자체 종료 제스처는 브라우저 권한에 속하며, 해제 후 시작 버튼을 눌러 복귀합니다.

노트북에서 사이트를 열어 둔 상태로 사용합니다. 리모컨에는 발표 내용과 참가자 현황을 표시하지 않습니다. 노트북의 전체화면은 해당 노트북에서 전환합니다. 관리 화면에서 관리자 기기를 각각 연결 해제할 수 있으며, 관리자 이름을 변경하면 모든 기존 관리자 기기의 권한이 해제됩니다. 명단 편집, 참가자 기기 연결 해제와 관리자 지정은 기본 사이트의 관리 화면에서 진행합니다.

## 첫 번째 레크레이션 · 취향을 읽어라

- 4번 화면에서 게임 방법을 소개합니다. 선택지는 피트·셰리·버번 3개이며 `src/taste-model.js`의 `WHISKY_OPTIONS`에서 관리합니다.
- 5번 화면의 리모컨에서 **투표 시작 → 투표 종료**로 개인 취향을 모읍니다. 이어서 **최다 득표 예상 투표 시작 → 예상 투표 종료**로 가장 인기 있을 항목을 예상하게 합니다. 각 단계는 1인 1표이며 제출 후 변경할 수 없습니다. 취향 투표가 한 표 이상 있으면 종료할 수 있습니다.
- 공동 최다 득표 항목은 모두 정답으로 인정합니다. 미투표자는 득점하지 않습니다. 예상 투표가 끝나면 6번 화면으로 이동할 수 있습니다.
- 6번 화면에는 게임 시작 시 명단을 고정해 표시합니다. **결과 공개**를 누르면 정답자만 무작위 순서로 0.14초 간격으로 점등합니다. 공개가 끝나면 다음 화면으로 이동할 수 있습니다.
- 7번 화면 진입 시 정답자 1명당 해당 팀에 10점을 가산하고 순위 이동과 점수 증가를 표시합니다. 동점 팀은 공동 순위로 표시하며 같은 점수 안에서는 조 번호 순서로 배치합니다. 되돌아가기·재접속·동시 화면 이동에도 같은 라운드의 점수는 한 번만 가산합니다.
- 8번 화면에서는 **참이슬·처음처럼·진로·새로**로 같은 투표를 진행합니다. 9번에서 정답자를 공개하고, 10번에서 소주 라운드 점수를 위스키 점수에 더합니다. 두 라운드의 표와 결과는 독립적으로 저장하며, 이전 화면으로 돌아가도 중복 가산하지 않습니다.

위스키는 `tasteGame`, 소주는 `sojuGame`, 누적 점수는 `teamScores`에 저장됩니다. 결과 공개 전의 투표 내역과 정답 계산은 행사 소유자·등록 관리자만 조회합니다. 참여자는 자신의 투표와 현재 라운드의 진행 상태를 조회합니다. 휴대폰은 투표 중에만 선택 버튼을 표시하고 나머지 시간에는 **대기 중**을 표시합니다.

이 기능은 추가된 Firebase Database 규칙이 필요합니다. 규칙은 로컬 에뮬레이터에서 검증하며, 실제 Firebase 반영은 명시적 승인 후 진행합니다.

## 중요한 구분

- 관리 주소는 기본 사이트 주소입니다. 참가자 주소는 QR에 담긴 `?room=행사ID` 주소입니다.
- 명단의 브라우저 저장본은 로컬 테스트와 실제 연결을 구분해 보관합니다. 로컬 에뮬레이터 데이터가 초기화되어도 입력한 명단을 복원할 수 있으며, 브라우저 데이터를 지우면 저장본도 삭제됩니다.
- 공용 행사의 관리 권한은 원래 소유자와 등록된 관리자 이름으로 로그인한 기기에 부여됩니다. 참가자 기기에는 관리 권한이 부여되지 않습니다.
- 브라우저 데이터를 삭제하거나 다른 컴퓨터로 이동하면 등록된 관리자 이름으로 다시 로그인합니다. 저장된 명단, OX 문제와 사진은 같은 Firebase 행사에서 불러옵니다.
- 운영 사이트에서는 브라우저별 새 행사를 생성하지 않습니다. `?room=`에 이전 행사 ID가 있어도 공용 행사로 연결합니다. 로컬 에뮬레이터는 기존의 독립 행사 테스트를 유지하며, `VITE_FIXED_EVENT_ROOM`으로 공용 행사 흐름을 검증할 수 있습니다.
- 실명 입력은 명단 매칭이며 본인 인증은 아닙니다. 초대받은 사람이 자기 이름을 입력하는 행사 운영을 전제로 합니다.
- 참가자는 명단 전체나 다른 사람의 응답을 읽을 수 없습니다.
- 현재 화면은 **입장 안내·선착순 터치** 시연용입니다. 채팅 화면은 제거했으며 기존 데이터나 보안 규칙은 변경하지 않았습니다.
- 순위는 휴대폰의 시계가 아닌 **서버 접수 시각**으로 결정합니다. 통신 지연에 따라 실제 손이 닿은 순서와 다를 수 있습니다. 같은 밀리초의 응답은 관리자에게 먼저 전달된 결과를 유지합니다.
- 모바일은 이름 입력 후 가로 전체화면으로 진행합니다. 터치 단계에서는 화면 전체가 입력 버튼입니다. 입장 후 세로로 돌리면 회전 안내가 표시됩니다.
- 전체화면은 브라우저 정책상 첫 터치가 필요합니다. 지원되는 브라우저에서는 시작 버튼으로 전체화면과 가로 고정을 요청하고, 전체화면을 벗어나면 다시 시작 버튼을 표시합니다. 전체화면이나 방향 고정을 지원하지 않는 브라우저는 기기를 직접 가로로 돌려 사용합니다. 웹페이지가 브라우저 주소창까지 강제로 숨길 수는 없습니다.

## Firebase 설정

루트의 **`firebase-config.js`**에 공개 웹 설정을 입력합니다. 현재 기존 `martinimt-9c21f` 웹 앱 설정이 채워져 있습니다. 다른 프로젝트를 연결할 때는 `firebase-config.example.js`를 참고하세요.

이 파일에는 서비스 계정 JSON, 비공개 키, Admin SDK 키, OAuth 토큰을 넣으면 안 됩니다. 공개 웹 설정은 빌드 결과에 포함되며, 권한은 Authentication과 Security Rules로 제어합니다.

`appCheckSiteKey`는 선택적인 reCAPTCHA v3 공개 사이트 키입니다. App Check 강제 적용은 별도 승인 후 진행합니다.

## 로컬 개발

### 화면 스타일

색상·글자·간격 공통 토큰은 `src/design-tokens.css`, 화면별 스타일은 `src/event-style.css`에서 관리합니다. 차콜 배경과 골드 행동 버튼을 사용하며, 명단 관리·발표·참가자 페이지의 기존 기능과 구성을 유지합니다. 관리 화면에는 사진이나 홍보용 히어로를 사용하지 않습니다. 관리자 화면은 최소 1120px의 컴퓨터용 네 조 배치를 사용하고, QR로 연결하는 참가자 화면은 모바일 폭과 터치 입력에 맞춥니다.

Pretendard Variable은 설치한 패키지의 동적 서브셋을 빌드에 포함해 필요한 글자 파일만 로드합니다. 별도 폰트 CDN 연결 없이 동작합니다. 화면은 장식 아이콘과 영문 슬로건 없이 기능 중심의 한국어 문구를 사용합니다. 글꼴 라이선스는 `public/licenses/`에 있습니다.

Node.js 24.12 이상을 사용합니다.

```powershell
npm ci
npm run dev
```

노트북에서는 `http://localhost:5173/`로 접속합니다. 휴대폰은 같은 Wi-Fi에 연결한 뒤 터미널에 표시된 **Network 주소**로 접속합니다. 휴대폰의 localhost는 노트북을 가리키지 않습니다. 공유기의 기기 간 통신 및 Windows 방화벽 설정에 따라 접근이 달라질 수 있습니다.

실제 Firebase에 연결하는 로컬 개발 화면의 QR은 Vite가 확인한 노트북의 Network 주소를 사용합니다. GitHub Pages에서는 게시된 사이트 주소를 사용합니다.

개발 서버에서는 소스를 저장하면 화면이 갱신됩니다. GitHub Pages 화면은 새 빌드가 배포된 후 바뀝니다.

`npm run dev`는 로컬 화면에서 실제 Firebase에 연결합니다. 기존 로컬 에뮬레이터 명단이 있고 실제 Firebase 행사 명단이 비어 있으면 해당 입력을 이어서 사용합니다. 개발·테스트는 로컬 에뮬레이터에서 진행합니다. 사용자 기능 변경 요청은 `AGENTS.md`의 사전 승인 범위에 따라 검증 후 커밋·GitHub 업로드·게시 완료 확인까지 자동으로 진행합니다. `npm run build`는 로컬 빌드만 생성합니다.

## 배포

운영 반영은 `AGENTS.md`의 사전 승인 범위와 `SECURITY.md`의 보안 경계를 따릅니다. 에이전트는 기능 변경을 검증한 뒤 필요한 호환 규칙을 먼저 반영하고 `codex/live-chat` 푸시로 Pages 게시를 실행하여 완료까지 확인합니다. 인증·도메인·호스팅 설정 변경은 별도 승인을 받습니다.

1. Firebase Authentication의 익명 로그인을 활성화합니다.
2. 사용할 인증 도메인을 확인합니다. 도메인 설정만으로 데이터베이스 접근이 보호되지는 않습니다.
3. 변경한 규칙을 로컬 에뮬레이터에서 검증합니다. 규칙 생성 원본은 `scripts/generate-rules.mjs`입니다.

   ```powershell
   node scripts/generate-rules.mjs
   ```

4. 사전 승인 범위의 규칙 변경은 운영 규칙과 비교하고 기존 경로·접근 제한·웹 버전 호환성을 확인한 뒤 배포합니다.

   ```powershell
   firebase deploy --only database --project martinimt-9c21f
   ```

5. GitHub 저장소 Settings → Pages → Source를 **GitHub Actions**로 설정합니다.
6. `codex/live-chat` 푸시는 `.github/workflows/pages.yml`에서 검사·빌드·게시됩니다. 에이전트는 배포한 커밋의 게시 성공과 운영 페이지를 읽기 전용으로 확인합니다.

게시 주소: `https://nacha4.github.io/MartiniMT/`

현재 구조에는 Cloud Functions나 관리자 키가 필요하지 않습니다. 요금제를 코드로 변경하지 않습니다.

## 검증

```powershell
npm test
npm run build
```

Firebase CLI와 Java 21 이상을 준비하고 별도 터미널에서 로컬 에뮬레이터를 실행합니다.

```powershell
firebase emulators:start --only auth,database --project demo-martini-mt
```

다른 터미널:

```powershell
$env:FIREBASE_DATABASE_EMULATOR_HOST = '127.0.0.1:9000'
npm run test:rules
npm run test:e2e
```

브라우저 검사는 설치된 Chrome과 전용 `127.0.0.1:5174` 에뮬레이터 화면을 사용합니다. 로컬 개발 화면과 함께 실행할 수 있습니다. 에뮬레이터 화면은 `npm run dev:emulators`로도 열며 **로컬 테스트** 표시가 붙습니다.

검증 범위: 행사 소유자 권한, 명단 비공개, 동명이인 조회, 기기 연결 원자성, 동시 중복 연결 차단, 관리자 연결 해제, 개인 안내와 응답의 접근 제한, 응답 시각·라운드 위조 차단, 기존 채팅 규칙의 접근 제한. 브라우저 검사에서는 24명 명단의 QR 화면, 두 휴대폰의 입장·대기·터치, 최초 응답 결과, 새 라운드 초기화, 좌우 클릭 이동, 전체화면, 모바일 가로 넘침을 확인합니다.

## 데이터와 운영

- 경로는 `/mtChatV1/sessions/{행사ID}`이며, 다른 데이터 경로는 기본 차단입니다.
- 이름, 조, 기기 연결 정보와 라운드 응답은 Firebase에 보관됩니다. 과거 채팅 데이터나 행사는 자동 삭제되지 않습니다. 보존·삭제 정책은 별도로 정해야 합니다.
- 전송 중 페이지를 닫으면 전송이 보장되지 않습니다. 접속자 상태에는 네트워크에 따른 지연이 있을 수 있습니다.
- 실제 휴대폰 24대와 현장 Wi-Fi에서 최종 리허설을 권장합니다.
